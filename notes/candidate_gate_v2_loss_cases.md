# Candidate Gate-v2 Loss Case Audit

Date: 2026-09-05

## Setup

Analyzed:

```text
data/scored/candidate_gate_v2_l2_02/candidate_gate_v2_cv_mean_rank.jsonl
```

Main method:

```text
candidate_gate:candidate_gate_v2_cv
open_math_prm aggregation: mean
normalization: rank
l2: 0.02
```

The current mixed subset is not labeled by a separate human problem type. It is
formed by candidate correctness labels:

```text
mixed problem = at least one generated candidate is correct and at least one is wrong
```

The labels used by Candidate Gate-v2 are candidate-level `is_correct` labels.
They are generated by the current answer checker and are represented below as
truth strings, where `C` means the candidate is labeled correct and `W` means it
is labeled wrong.

Important: Candidate Gate-v2 currently does not encode the full problem text. It
uses candidate/expert score features and shallow candidate text statistics, such
as solution length, step count, score rank, expert-top indicators, and aggregate
open-source/OpenAI score statistics.

## Main finding

Most current Candidate Gate-v2 losses are likely answer-label normalization
artifacts rather than true semantic selection failures.

Under the current strict answer checker, all 12 cases above are counted as
wrong. Under the simple loose diagnostic, 11 of 12 become answer-equivalent to
the gold answer. The only clearly semantic V2 loss in this audit is:

```text
bbh_logical_deduction_seven_objects_0077
```

For this logic case, the correct candidates are `000` and `001`, while Candidate
Gate-v2 selects `006`. The expert top choices are:

```text
open_math_prm             -> 000, correct
open_reasoning_rm         -> 001, correct
openai_general_judge      -> 006, wrong
openai_reflective_judge   -> 006, wrong
```

This is a real gate failure: two OpenAI judge-style experts agree on a wrong
logic candidate, and Candidate Gate-v2 follows that misleading score pattern.

## Implication for Gate-v3

Training Gate-v3 immediately is probably not the best next step. The dataset is
small, and the apparent loss set is dominated by label-normalization noise.
Before adding a more expressive model, the cleaner next move is:

```text
1. Improve or audit answer normalization, especially inline LaTeX delimiters.
2. Re-label the existing candidate files.
3. Re-run expert/gate evaluation on the corrected labels.
4. Only then decide whether a text-aware Gate-v3 is still needed.
```

Encoding the full problem is still a plausible next direction, but it should be
done carefully:

```text
Good low-risk version:
- freeze a text embedding model;
- encode only the problem statement, not the gold answer;
- concatenate a small compressed embedding or LLM-generated problem tags with
  current V2 score-pattern features;
- train only a small regularized classifier/router with problem-level CV.

Risky version:
- fine-tune a text encoder or use high-dimensional embeddings directly on only
  84 mixed problems.
```

For the current course project, a conservative framing is:

```text
Candidate Gate-v2 already improves over strong baselines on the noisy labels.
The loss audit suggests that further gains should first come from label hygiene,
not a larger gate model. A problem-text-aware gate can be positioned as future
work or a small optional diagnostic, rather than the main next experiment.
```

## Follow-up

This recommendation was tested in the 2026-09-05 label-cleanup experiment:

```text
notes/label_cleanup_v2_results.md
```

After conservative answer-checker cleanup, the old Candidate Gate-v2 selections
score:

```text
83 / 84 = 0.988
```

The retrained all-84 clean-label Candidate Gate-v2 scores:

```text
82 / 84 = 0.976
```

This supports the conclusion that label hygiene, not a larger Gate-v3, is the
right immediate next step.
